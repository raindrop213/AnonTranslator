## 1.5.3：Google 网络失败也尝试备用接口

此前 `googleChunk` 仅在 429、403、缺少权限或网页没有结果时回退。Chrome 已有权限但 fetch 断连后，权限适配层生成的连接错误被直接抛出，备用入口完全没有请求。这与用户提供的 `translate.google.com` 连接失败提示一致。

## 1.5.2：指定网站下的接口权限

用户报告只允许特定网站时翻译变为 `Failed to fetch`。代码确认翻译已经通过 service worker 发起，原问题缺少运行时权限检查：声明 `host_permissions` 不代表被用户扣留的接口权限仍可用。根据 Chrome 官方说明，后台 `fetch` 同样依赖目标域名权限；这一触发条件与只授权阅读网站、未授权翻译接口相符，但未直接读取用户当前 Chrome 的授权状态。

增加 `platform/chromePermissions.js`，限制请求到已有服务域名，并在请求前用 `chrome.permissions.contains` 检查。缺失时显示接口名称、域名及对应授权入口；连接失败时复查是否中途撤销，区别权限问题与网络故障。Google 主入口没有权限时可尝试已经授权的备用入口。

Chrome 设置面板新增按服务授权按钮，由用户直接点击调用 `chrome.permissions.request`，不经过设置保存队列，不自动索要权限。只申请原 manifest 已声明的具体接口域名，保留用户的指定阅读网站限制；VITS 同样提供本地域名授权。油猴继续使用原 GM 请求路径。

20 项逻辑 / 构建测试及浏览器回归通过。Chrome 权限 API 的模拟测试覆盖接口缺失时不发请求、授权拒绝、用户手势内精确域名授权、授权后同文本重试、Google 仅备用域名获准、请求中途撤销、普通网络错误。实际 Chrome 网站权限提示与线上服务连接仍需用户更新扩展后验证。依据：[Chrome 跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、[被扣留权限的请求与检查](https://developer.chrome.com/docs/extensions/reference/api/permissions#method-request)。

## 1.3.0：句子导航与服务修复

阅读状态统一为“所在段落 + 可选句子 + 当前模式”。段落模式处理整段，句子模式只处理当前句；翻译目标与复制 / 朗读目标一致。段落标记在句子模式变成虚线，句子片段持续高亮并描边。句后译文是独立兄弟节点，不参与后续提取、断句或排序。句子跨 span、em、b 与 ruby 时，通过同一个句子索引关联多个片段，保留原有元素与监听器。

默认 1 / 2 为下一段 / 上一段，4 / 5 为下一句 / 上一句，均支持主键盘与小键盘；箭头段落键仍保留。下一句到段尾会进入下一段第一句，上一句到段首会进入上一段最后一句；从段落模式进入句子模式时，下一句定位首句、上一句定位末句。段落键始终切回段落模式。重读与自动阅读沿当前模式工作。快捷键独立模块负责按键代码、修饰键、备用键与冲突校验；设置界面支持录制与恢复默认。

DeepL 与彩云已从当前界面、默认配置、服务实现和两平台授权移除。旧存储中的这些键会被设置归一化忽略。

有道原接口实测：12 字测试文本 HTTP 200，840 字 HTTP 413。新增每块最多 180 个 Unicode 字符的串行翻译，尽量在标点处切分，遇到 413 继续二分，译文按原顺序合并。修复后同一 840 字文本已真实请求成功。分块不能保证不同块之间的翻译上下文一致，句子模式通常更适合阅读长段落。

Google 与初始版本对照后，恢复原版的 Accept 和 Accept-Language；显式 User-Agent 在 Chrome fetch 中不能作为可靠修复。原版与重构版均请求 `/m`，基础端点没有改变。新增网页接口受限时的公开 JSON 备用入口、请求去重 / 成功缓存、串行调度与双入口 429 后一分钟暂停。当前网络下原版请求、新版请求、JSON 入口均连接超时，无法用实测证明 429 是请求头改变导致。备用解析与限流行为有模拟回归，真实 Google 可用性仍待用户网络验证。

VITS 本地实测：23456 的 `/voice/speakers` 返回 804 个声音，8666 没有服务。新版直接合成 MP3 并由浏览器播放，移除桥接依赖，参数 max 正确映射到 segment_size。默认声音 342 实测得到 15923 字节 MP3，生成的音频在无头 Chrome 中正常播放，停止键验证通过。停止会取消浏览器播放并忽略过期响应，不会中止服务端已经开始的计算。

当前测试覆盖段落 / 句子双模式、跨段边界、持续选中标记、句后译文、快捷键录制与冲突、嵌套 markup、ruby、竖排布局与 VITS 音频。Chrome / GM 平台 API 仍使用模拟对象，真实扩展授权和脚本管理器差异不在该浏览器回归内。下文是 1.2.0 重构背景与当时的验证范围。

原版是一个无构建流程的 Manifest V3 扩展：content.js 集中了文本、DOM、键盘、语音与翻译显示，background.js 同时负责默认配置初始化和接口请求，popup.js 手工读取表单。三个文件直接依赖 Chrome API，使油猴导出需要复制和改写业务逻辑。

| 删除整个 style 属性，损坏网页原样式 | 只保存与还原 outline、border-radius 两个属性 |
| innerHTML 重建段落和删除所有 span，破坏事件监听与 markup | 移动现有节点包装句子；清理文本使用 DOM 克隆，不改页面 |
| 导航只沿 DIV 首 / 末子节点查找，会跳过容器里的文本 | 用文档顺序的有效目标段落导航，支持 section、article 等容器 |
| 未选段落时空格自动阅读访问 null；输入框内也触发快捷键 | 验证选中段落，过滤可编辑目标、组合键、输入法与重复按键 |
| 停止后异步回调可能继续排入下一段，结束后状态不复位 | generation 标记阻止旧流程继续，停止清理定时器，末段后退出 |
| 不开启朗读时调用未定义 callback；关闭复制后无回调 | 阅读统一为 Promise，不依赖复制成功与否推进 |
| 无效数值作为字符串保存，pitch=0 被默认值覆盖 | 集中校验与数值归一化，合法的 0 保留 |
| 声音已加载时只等待 onvoiceschanged，列表可能为空 | 立即加载并监听后续变化 |
| 有道请求 m.youdao.com，但 manifest 授权 aidemo.youdao.com | 两个平台授权实际请求域名 |
| Google 用 decodeURIComponent 解码 HTML，遇到 % 抛错 | 专门解码 HTML entity，保留百分号 |
| 彩云使用浏览器没有的 Buffer，含旧的硬编码令牌 | TextDecoder + atob 处理 UTF-8，由用户配置令牌 |
| API 响应未判空，播放失败不能明确反馈 | 统一错误处理、超时与响应校验，界面显示错误 |
| 老翻译响应可能插入新的翻译容器 | 回调仅更新自己创建且仍连接的容器 |
| 设置事件与主动保存通知重复触发翻译请求 | 归一化后按实际改变去重通知 |
| 帮助将空格错误标成 Backspace | 帮助与实际快捷键一致 |

## 设计取舍

不引入框架和构建依赖。构建脚本明确列出每个入口的模块顺序，将源码组合成闭包并嵌入默认数据；源码只维护一份。平台适配只负责存储、变更通知、消息与剪贴板。翻译 / VITS 服务接受请求函数，因此 Chrome fetch 与油猴 GM 请求使用同一套逻辑。

设置界面改成分组折叠面板，复用输入校验和选项定义。油猴使用 Shadow DOM 隔离网页 CSS；Chrome 使用同一界面作为弹窗。旧背景图片和预览移到文档目录，发行包只复制图标。

Chrome local 避免 sync 的短期写入限额，适合即时保存。代价是移除了自动跨设备同步。原 sync 数据保留不删除；迁移按扩展 ID 读取。构建同时提供根目录兼容入口，已有未打包安装可以沿用原目录。

## 验证范围与后续边界

自动逻辑与构建测试覆盖设置校验、迁移优先级、事件去重、HTML / 彩云解码、GM 适配、播放地址限制、错误传播与生成文件完整性。无头 Chrome 回归直接加载生成的油猴脚本，以及生成的 Chrome 后台 / 弹窗（平台 API 模拟），验证 ruby 提取、句子右键、导航、即时设置、样式还原、元素监听器保留、翻译展示、自动阅读停止与面板布局。

1.2.0 时未在真实安装的 Chrome 扩展或 Tampermonkey 中验证授权与框架注入，外部接口与本地 VITS 当时也未测试；1.3.0 的实测情况见上文。网页翻译接口本身没有稳定契约，若需要长期维护，建议后续改成有正式鉴权与错误约定的服务接口。

1.2.0 只在段落直接文本节点的标点处分割，1.3.0 已支持跨嵌套内联元素的句子片段。ruby 保持整体，不在 ruby 基本文字内部进一步拆句。动态新增段落由事件委托直接处理，不需要 MutationObserver。封闭 Shadow DOM、canvas 文本与纯文本页面不属于当前提取目标。

1.3.0 已移除旧 VITS 桥接，改为可停止的浏览器音频播放。系统声音仍按原项目的数字序号配置，换浏览器 / 系统后顺序可能不同，需要重新选择。其余沿用的配置键名便于迁移。
